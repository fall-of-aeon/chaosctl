# chaos-n8n / chaosctl

AI-driven chaos engineering for [n8n](https://github.com/n8n-io/n8n) (queue mode) on a local Kind cluster.
Built for the Bosch Hackathon "AI-Driven Chaos Engineering for Cloud-Native Resilience".

- **Target app:** n8n main + worker + Redis + Postgres + a mock downstream API, running three small workflows
  (W1 sync webhook, W2 async webhook, W3 cron heartbeat).
- **Dependency graph:** Kubernetes discovery (workloads, Services, ConfigMap env) + a declared overlay
  (`chaosctl/overlay.yaml`). It computes blast radius, single points of failure and criticality.
- **Agent 1 (injection, LangGraph + Gemini):** deterministic scorer -> Gemini selects and explains, citing graph IDs
  -> validator -> deterministic **policy guard** (tier rules, blast radius, abort thresholds). Any LLM failure falls
  back to a deterministic plan.
- **Execution and safety (deterministic, never LLM-controlled):** Chaos Mesh resources are created only from
  catalog templates, only in namespace `n8n-chaos`. A 1 Hz abort monitor runs in its own thread. A kill switch works
  three ways (`chaosctl kill`, `./KILL` file, SIGINT/SIGTERM), and a recovery watchdog handles one-shot faults.
- **Evidence:** a load generator records every request. Probes (Redis queue, Postgres reconciliation,
  pod state) produce a per-request **fate table** (completed / lost silently / duplicated / phantom success /
  lost visibly) and a recovery timeline.

## Status

Work in progress; see `docs/PROGRESS.md` for what has been verified live and `docs/FACTS.md` for checked facts.
Experiments today: **E1** worker pod kill during execution, **E2** Redis restart during execution.

## Requirements

Docker (6 GB+ memory for Docker Desktop), kind, kubectl, Helm, [uv](https://docs.astral.sh/uv/), a Gemini API key
(optional: everything works with the deterministic fallback).

## Setup and run

```bash
cp .env.example .env              # add GEMINI_API_KEY (optional)
uv sync
uv run chaosctl cluster-up        # Kind + kube-prometheus-stack + Chaos Mesh
uv run chaosctl up                # postgres, redis, mock-api, n8n (baseline profile)
uv run chaosctl bootstrap         # import + activate workflows, smoke test
uv run chaosctl graph             # dependency graph, SPOFs, blast radius (also writes graph.mmd)
uv run chaosctl baseline --duration 120
uv run chaosctl plan --dry-run    # agent's ranked plan with reasons and guard verdicts
uv run chaosctl run --exp E1      # then --exp E2
uv run chaosctl kill              # kill switch (or: touch KILL)
uv run chaosctl recover --ack
uv run pytest                     # unit tests, no cluster needed
```

Everything runs inside the local Kind cluster `chaos`; the harness refuses any other kube context.
